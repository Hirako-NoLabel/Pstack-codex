# Shared design task

This is an isolated greenfield acceptance fixture for PStack architect + arena, not a new production feature. Design a small asynchronous, per-key loading cache for Node JavaScript callers. Required behavior: concurrent loads for one key share one pending computation; different keys proceed independently; successful values are reused until a positive configurable TTL measured from successful completion; failure is not cached; invalidate(key) prevents an old pending operation from installing stale data yet preserves its original caller's eventual result. A request after invalidation must start a fresh operation even if the old one remains pending. The supplied clock and loader enable deterministic tests. No networking, timers, persistence or external packages. Undefined is a valid cached value. Reject invalid TTL at construction.

Produce usage first, a typed sketch with not-implemented bodies/pseudocode, module map and rationale using the shipped rationale template. Explicitly compare at least two structurally distinct ownership/state shapes and choose one. Do not implement yet. Phase A is greenfield; there is no surrounding subsystem to trace. Read the supplied runner template verbatim as instructions and the actual architect skill. Keep all artifacts inside your assigned candidate directory; do not inspect sibling candidates or rubric. Default inherit-parent model. No external writes.

Boundary clarification sent to all runners: loader can throw synchronously; get returns a rejected promise and permits retry. Reentrant loader calls for the same key join published pending work; self-await cycles are out of scope.
