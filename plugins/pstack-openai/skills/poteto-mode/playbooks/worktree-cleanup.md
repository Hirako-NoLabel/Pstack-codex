### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

1. Snapshot and audit. Record available disk space using the host tool, then run `node scripts/worktree-audit.mjs --repo <repo> --base <verified-trunk-ref>`. Add `--size` for disk byte totals and `--with-prs` for optional read-only GitHub PR-state lookup. Age and remote-ref status are included; PR closed state alone never proves merge. This portable tool parses NUL-delimited Git paths, preserves spaces and Unicode, and never fetches or deletes. It reports tracked, untracked, ignored, merged, locked, and usage state. Supply `--active-file <json>` only with an explicit JSON list derived from real active/pinned task evidence. Without that evidence every clean row remains `verify-usage`, never safe.
2. The bucket is advice, not permission. The pinned and active chats are the real artifact (principle-prove-it-works). Get that set from the user or sidebar and cross-check every candidate. The lever has marked `safe` a worktree the user had pinned, so the pinned set wins.
3. Verify usage before deleting. Inspect host task state or ask for usage evidence when unavailable. Follow delegated worktree references too. Do not infer inactivity from transcript timestamps, branch age, or absence from a sidebar.
4. Protect user work. `hold-wip`, `hold-untracked`, `hold-ignored`, `hold-active`, `hold-locked`, and `hold-unreadable` are not cleanup candidates. Show the relevant paths and obtain a decision before deletion that would lose data. Untracked files are not automatically scratch. A closed PR is not proof of merge. `candidate-clean-merged` is evidence for review, not deletion authorization.
5. Prune only the authorized confirmed set. Resolve and validate each path against the repository worktree inventory immediately before removal. Prefer `git worktree remove <path>` without force. If it refuses, inspect the reason; do not bypass protection automatically. Native filesystem removal of leftovers requires checked absolute paths and explicit coverage in the authorization. Re-list worktrees and compare available disk space. Branch refs survive ordinary worktree removal.
6. Simulators and other reclaimers. On macOS only, inspect Xcode simulator state, unavailable devices, old runtimes, DerivedData and iOS DeviceSupport. Delete only specifically authorized inactive simulator/cache targets. On Windows or Linux this stage is not applicable. Preserve the upstream Cursor cache cleanup capability as an optional explicit target when Cursor is installed; never translate it into deleting Codex state. Inspect cache sizes and keep the user's exclusions.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** available disk space before and after with space reclaimed (`Get-PSDrive -PSProvider FileSystem` on Windows, `df -h` on macOS/Linux), the worktrees pruned, and a one-line reason for each held back (in-use by which chat, or uncommitted work).
